# НАЧНИ ОТСЮДА — задача Greenterest и ML-метрики с абсолютного нуля

Этот файл — **нулевой уровень**. Здесь не предполагается, что ты знаешь, что такое Recall, Precision, F1, Specificity, label, score, ranking, positive/negative, TP/FP/FN/TN.

---

# 1. Что вообще происходит в задаче

Есть сайт **Greenterest** с большим количеством картинок.

Пользователь вводит запрос, например:

```text
green futuristic city
```

В базе могут быть тысячи картинок. Сайт должен решить:

> Какие картинки показать пользователю первыми?

Он не может просто вывалить 50 000 изображений в случайном порядке. Нужен алгоритм, который поставит наиболее подходящие изображения наверх.

Пример выдачи:

```text
1. image_A
2. image_B
3. image_C
4. image_D
...
20. image_T
```

Такой упорядоченный список называется **ranking** — ранжирование.

---

# 2. Что такое SERP

В условии встречается:

```text
SERP = Search Engine Result Page
```

Это просто **страница поисковой выдачи**.

Когда ты вводишь запрос в Google и видишь список результатов — это SERP. В Greenterest SERP состоит из картинок.

---

# 3. Откуда мы знаем, какая картинка хорошая

У нас есть история старой системы.

Вчера пользователь искал:

```text
green cyberpunk city
```

Старая система показала ему 20 картинок. Пользователь кликнул, например, по:

```text
A, D, H, Q
```

В учебной задаче мы используем исторические клики как приближение к истине:

```text
кликнул     -> считаем релевантной
не кликнул  -> считаем нерелевантной
```

В реальном продукте клик — не идеальная истина: пользователь мог не увидеть хорошую картинку, мог кликнуть случайно, позиции влияют на клики. Но для этой задачи принимаем клики как target.

---

# 4. Что значит «релевантная»

**Релевантная** = подходящая запросу / полезная пользователю.

Запрос:

```text
red sports car
```

Красная Ferrari — вероятно релевантна.

Зелёная лягушка — вероятно нерелевантна.

В задаче это кодируется числами:

```text
1 -> релевантна
0 -> нерелевантна
```

---

# 5. Что такое label

Есть список:

```python
labels = [1, 0, 1, 0, 1]
```

Он означает:

```text
картинка A -> 1 -> релевантна
картинка B -> 0 -> нерелевантна
картинка C -> 1 -> релевантна
картинка D -> 0 -> нерелевантна
картинка E -> 1 -> релевантна
```

`label` — это **известный нам правильный ответ**.

Упрощённо:

```text
label = truth
```

В этой задаче:

```text
1 = был клик
0 = клика не было
```

---

# 6. Что такое новая модель

Мы хотим проверить новый алгоритм поиска до запуска на реальных пользователях.

Новая модель получает:

```text
запрос + картинку
```

и выдаёт число — насколько картинка кажется ей подходящей.

Например:

```python
scores = [0.95, 0.10, 0.80, 0.20, 0.70]
```

Это **scores**.

Условно:

```text
0.95 -> модель считает картинку очень релевантной
0.80 -> довольно релевантной
0.20 -> скорее нерелевантной
0.10 -> совсем плохой
```

Важно:

```text
label = историческая «истина»
score = мнение новой модели
```

Score не обязан быть вероятностью. Для Top-K нам главным образом важен порядок: чем больше score, тем выше объект.

---

# 7. Labels и scores относятся к одним объектам

```python
labels = [1, 0, 1]
scores = [0.30, 0.95, 0.80]
```

Это пары:

| Картинка | label | score |
|---|---:|---:|
| A | 1 | 0.30 |
| B | 0 | 0.95 |
| C | 1 | 0.80 |

Читаем:

- A реально хорошая, но модель оценила её низко.
- B реально плохая, но модель ошибочно дала высокий score.
- C хорошая и получила высокий score.

Нельзя отдельно сортировать `labels` и `scores`: тогда потеряется связь с конкретной картинкой.

---

# 8. Как из scores получается поисковая выдача

Сортируем объекты по score **по убыванию**.

Было:

```text
A: label=1, score=0.30
B: label=0, score=0.95
C: label=1, score=0.80
```

Стало:

```text
1. B: label=0, score=0.95
2. C: label=1, score=0.80
3. A: label=1, score=0.30
```

Это ranking новой модели.

---

# 9. Что такое Top-K

`K` — просто число первых результатов, которые нас интересуют.

```text
K = 5 -> первые 5 результатов
K = 10 -> первые 10
K = 20 -> первые 20
```

Почему не смотреть весь список?

Потому что пользователь обычно видит верх выдачи. Идеальная картинка на позиции 700 почти бесполезна.

---

# 10. Что означает знак @

```text
Recall@5
Precision@10
F1@20
Specificity@20
```

читается как:

> метрика, рассчитанная для Top-K.

Например:

```text
Recall@20 = Recall для первых 20 результатов
```

---

# 11. Главный трюк этой задачи

Для расчёта этих метрик считаем:

```text
Top-K          -> модель ВЫБРАЛА
ниже Top-K     -> модель НЕ ВЫБРАЛА
```

А по label знаем:

```text
1 -> реально хорошая
0 -> реально плохая
```

Теперь для каждой картинки задаём два вопроса:

1. Реально хорошая или плохая?
2. Модель выбрала её в Top-K или нет?

Из этого появляются четыре случая.

---

# 12. TP, FP, FN, TN человеческим языком

## TP — True Positive

```text
Реально хорошая? ДА
В Top-K?         ДА
```

Хорошая картинка правильно попала наверх.

Это успех.

---

## FP — False Positive

```text
Реально хорошая? НЕТ
В Top-K?         ДА
```

Плохая картинка ошибочно попала наверх.

Это ошибка.

---

## FN — False Negative

```text
Реально хорошая? ДА
В Top-K?         НЕТ
```

Хорошая картинка осталась далеко внизу.

Это ошибка.

---

## TN — True Negative

```text
Реально хорошая? НЕТ
В Top-K?         НЕТ
```

Плохая картинка правильно осталась за Top-K.

Это успех.

---

# 13. Самая важная таблица всей темы

```text
                         РЕАЛЬНО
                      GOOD    BAD

МОДЕЛЬ ВЫБРАЛА         TP      FP

МОДЕЛЬ НЕ ВЫБРАЛА      FN      TN
```

В терминах ranking:

```text
                       ACTUAL
                 positive   negative

TOP-K               TP         FP

OUTSIDE TOP-K       FN         TN
```

Здесь:

```text
positive = label 1 = релевантно
negative = label 0 = нерелевантно
```

---

# 14. Один полный пример

Есть 10 картинок.

Реально хорошие:

```text
A, B, C, D
```

Реально плохие:

```text
E, F, G, H, I, J
```

Модель построила такой Top-5:

```text
A
B
E
F
C
```

Разбираем Top-5:

```text
A good -> TP
B good -> TP
E bad  -> FP
F bad  -> FP
C good -> TP
```

За пределами Top-5:

```text
D good -> FN
G bad  -> TN
H bad  -> TN
I bad  -> TN
J bad  -> TN
```

Получили:

```text
TP = 3
FP = 2
FN = 1
TN = 4
```

Теперь все четыре метрики — просто разные вопросы к этим четырём числам.

---

# 15. Что спрашивает Recall

> Из **ВСЕХ реально хороших** сколько мы нашли?

Всего хороших:

```text
TP + FN = 3 + 1 = 4
```

Нашли:

```text
TP = 3
```

```text
Recall = 3 / 4 = 0.75
```

То есть нашли 75% всех хороших картинок.

---

# 16. Что спрашивает Precision

> Из **ВСЕГО, ЧТО МЫ ВЫБРАЛИ**, сколько реально хорошее?

Всего в Top-5:

```text
TP + FP = 3 + 2 = 5
```

Хороших среди них:

```text
TP = 3
```

```text
Precision = 3 / 5 = 0.60
```

То есть 60% выбранных результатов хорошие.

---

# 17. Что спрашивает Specificity

> Из **ВСЕХ реально плохих** сколько мы правильно оставили за Top-K?

Всего плохих:

```text
TN + FP = 4 + 2 = 6
```

Правильно отбросили:

```text
TN = 4
```

```text
Specificity = 4 / 6 = 0.667
```

---

# 18. Что спрашивает F1

F1 пытается одной цифрой сказать:

> Насколько одновременно хороши и Recall, и Precision?

Если один очень высокий, а другой очень низкий, F1 тоже будет низким.

---

# 19. Почему нужны разные метрики

Представь систему, которая выбирает **вообще всё**.

Она точно не потеряет хорошие картинки:

```text
Recall будет высокий
```

Но она выберет море мусора:

```text
Precision будет плохой
```

Теперь другая крайность: система выбирает только одну картинку, в которой очень уверена.

Если она действительно хорошая:

```text
Precision = 100%
```

Но если всего хороших картинок было 100:

```text
Recall = 1%
```

Поэтому одной метрики недостаточно.


Для всех четырёх функций основа одна:

```text

2. scores = оценки модели

4. берём Top-K
5. определяем TP/FP/FN/TN
6. применяем нужную формулу
```

```python
labels = [1, 0, 1, 0]
```



```text

```

```text

```

Именно из этих чисел дальше считаются метрики.

# 22. Чего пока не нужно знать

Чтобы решить эту задачу, тебе не нужно понимать:

- нейронные сети;
- backpropagation;
- gradient descent;
- transformers;
- vector databases;
- loss functions.

Достаточно понять цепочку:

```text
история -> labels
новая модель -> scores
scores -> ranking
ranking -> Top-K
Top-K + labels -> TP/FP/FN/TN
TP/FP/FN/TN -> метрики
```

# 24. Мини-проверка себя

## Что такое label?

Исторически известный правильный класс объекта.

## Что такое score?

Число, которым новая модель оценивает релевантность объекта.

## Что такое ranking?

Объекты, отсортированные по score.

## Что такое Top-K?

Первые K объектов ranking-а.

## Что такое FP?

Плохой объект, который ошибочно попал в Top-K.

## Что такое FN?

Хороший объект, который не попал в Top-K.

# 25. Собеседование: базовые вопросы до самих метрик

## Почему click не идеальный ground truth?

Потому что click зависит не только от истинной релевантности, но и от позиции, интерфейса, того, увидел ли пользователь результат, и множества других факторов.

## Почему используется @K?

Потому что в поиске особенно важна верхушка выдачи, которую пользователь реально увидит.

## Score — это всегда вероятность?

Нет. Это может быть любое число, позволяющее корректно упорядочить кандидатов. Вероятность — частный случай score.

## Почему нельзя сортировать labels отдельно от scores?

Потому что score и label относятся к одному объекту. Независимая сортировка разрушает пары.
