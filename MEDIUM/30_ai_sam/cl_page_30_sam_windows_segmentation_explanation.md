рисует её. Это бесплатная проверка «тот ли файл я загрузил».

# ЧАСТЬ 4. Grounding DINO: текст → прямоугольники

## 4.1. Загрузка модели

```python
gdino_processor = AutoProcessor.from_pretrained(GDINO_MODEL_ID)
gdino_model = AutoModelForZeroShotObjectDetection.from_pretrained(GDINO_MODEL_ID)
gdino_model = gdino_model.to(DEVICE).eval()
```

**`from_pretrained(...)`** — «скачай и загрузи готовую обученную модель по этому адресу».
Первый запуск: скачивание с интернета в папку `~/.cache/huggingface`. Все следующие
запуски — мгновенно из кэша.

**Что такое `processor` и зачем он отдельно от модели.**
Модель принимает на вход только числа определённой формы. Процессор — это переводчик:

- картинку он **изменяет по размеру**, **нормализует** (вычитает среднее, делит на
  стандартное отклонение — так модель обучалась) и превращает в тензор;
- текст он **токенизирует**: режет на кусочки-токены и заменяет каждый на его номер
  в словаре.

Критично, что процессор берётся **от той же модели**: другая нормализация или другой
словарь — и модель получит бессмыслицу.

**`.to(DEVICE)`** — переносит все веса модели (сотни миллионов чисел) в память видеокарты.
Если `DEVICE == "cpu"`, ничего не происходит.

**`.eval()`** — переключает модель в режим предсказания. В режиме обучения некоторые слои
(dropout, batch normalization) ведут себя иначе. Мы не обучаем — значит, `eval`.
Забыть `.eval()` — классическая ошибка, дающая слегка плавающие результаты между запусками.

## 4.2. Подготовка входа

```python
inputs = gdino_processor(images=image, text=TEXT_PROMPT, return_tensors="pt").to(DEVICE)
```

| Аргумент | Что значит |
|---|---|
| `images=image` | наша картинка (PIL-объект) |
| `text=TEXT_PROMPT` | строка `"window."` |
| `return_tensors="pt"` | «верни результат в виде тензоров PyTorch». `pt` = PyTorch. Есть ещё `tf` (TensorFlow) и `np` (numpy) |

**Что лежит в `inputs`** (это словарь):

```
pixel_values      (1, 3, 800, 1333)   картинка после ресайза и нормализации
pixel_mask        (1, 800, 1333)      где настоящие пиксели, а где добивка
input_ids         (1, 5)              номера токенов текста
token_type_ids    (1, 5)              служебное для BERT
attention_mask    (1, 5)              где настоящие токены
```

Разбор формы `(1, 3, 800, 1333)` по осям:
- `1` — размер батча. Мы обрабатываем одну картинку. Модели всегда работают с батчами,
  даже если в батче один элемент;
- `3` — три цветовых канала;
- `800` — высота после ресайза;
- `1333` — ширина после ресайза.

⚠️ Обратите внимание: **порядок осей у PyTorch — `(батч, каналы, высота, ширина)`**,
а у numpy/PIL картинка была `(высота, ширина, каналы)`. Процессор переставил оси сам.

`input_ids` формы `(1, 5)` — строка `"window."` превратилась в 5 чисел, например
`[101, 3332, 1012, 102, 0]`, где 101 и 102 — служебные токены начала и конца.

**`.to(DEVICE)`** переносит все эти тензоры на видеокарту. Правило PyTorch:
**модель и данные обязаны быть на одном устройстве**, иначе ошибка.

## 4.3. Прогон через модель

```python
with torch.no_grad():
    outputs = gdino_model(**inputs)
```

**`with torch.no_grad():`** — контекстный менеджер, отключающий подсчёт градиентов.

*Что такое градиенты.* При обучении PyTorch запоминает каждую операцию, чтобы потом
посчитать, как менять веса. Это ест много памяти. Мы не обучаем — значит, запоминать
незачем. Отключение градиентов экономит примерно половину видеопамяти и ускоряет прогон.

**`**inputs`** — «распакуй словарь в именованные аргументы». То есть вместо
```python
gdino_model(pixel_values=..., pixel_mask=..., input_ids=..., ...)
```
пишем коротко `gdino_model(**inputs)`. Две звёздочки — это оператор распаковки словаря.

**Что в `outputs`:** сырые предсказания модели — `logits` формы `(1, 900, 256)` и
`pred_boxes` формы `(1, 900, 4)`. Модель всегда предлагает ровно 900 кандидатов
(это её архитектурная константа), большинство из них — мусор с околонулевой уверенностью.
Координаты в `pred_boxes` при этом нормированные (от 0 до 1) и в формате `cxcywh`
(центр + размеры). Пользоваться этим напрямую нельзя — нужен постпроцессинг.

## 4.4. Постобработка: отбор боксов и перевод в пиксели

```python
results = gdino_processor.post_process_grounded_object_detection(
    outputs,
    inputs.input_ids,
    BOX_THRESHOLD,
    TEXT_THRESHOLD,
    target_sizes=[(image.size[1], image.size[0])],
)
```

Эта функция делает четыре вещи:

1. Переводит логиты в вероятности и **выбрасывает кандидатов** со скором ниже `BOX_THRESHOLD`.
2. Сопоставляет оставшиеся боксы **словам промпта** с порогом `TEXT_THRESHOLD`.
3. Переводит координаты из формата `cxcywh` в `xyxy`.
4. Домножает нормированные координаты (0…1) на реальный размер картинки → пиксели.

**Про `target_sizes`.** Это ответ на вопрос «в каком разрешении мне вернуть координаты».
Мы хотим — в разрешении оригинала. Формат: список кортежей `(высота, ширина)` по одному
на картинку в батче.

`image.size` в PIL — это `(ширина, высота)` = `(1024, 1024)`.
Значит, `image.size[1]` — высота, `image.size[0]` — ширина.
Получаем `[(1024, 1024)]`.

⚠️ Для квадратной картинки перестановка незаметна. Для прямоугольной — все боксы
поедут, и вы получите маски в случайных местах без единого сообщения об ошибке.
Это тот баг, который ищут часами.

**Почему пороги переданы без имён (позиционно).**
В разных версиях `transformers` третий аргумент назывался то `box_threshold`, то
`threshold`. Если написать `box_threshold=BOX_THRESHOLD`, код упадёт на новых версиях.
Позиция аргумента при этом не менялась ни разу. Поэтому передаём позиционно — код
работает на любой версии.

```python
boxes = results[0]["boxes"].detach().cpu().numpy()
scores = results[0]["scores"].detach().cpu().numpy()
```

Разбираем цепочку слева направо:

| Кусок | Что делает |
|---|---|
| `results[0]` | результат для первой (единственной) картинки батча. Это словарь |
| `["boxes"]` | достаём из словаря тензор с координатами |
| `.detach()` | «отцепить от графа вычислений» — страховка на случай, если градиенты всё же считались |
| `.cpu()` | перенести тензор с видеокарты в обычную память. numpy не умеет читать память GPU |
| `.numpy()` | превратить тензор PyTorch в массив numpy |

**Форма `boxes`: `(N, 4)`**, где `N` — сколько окон нашлось. Каждая строка —
`[x_left, y_top, x_right, y_bottom]` в пикселях.

**Форма `scores`: `(N,)`** — по одному числу уверенности на бокс.

```python
print("Найдено окон:", len(boxes))
print("Уверенность: min = %.3f, max = %.3f" % (scores.min(), scores.max()))
```

`len(boxes)` для массива формы `(N, 4)` вернёт `N` — длину по первой оси.

`%.3f` — форматирование числа с тремя знаками после запятой.

**Это первая контрольная точка.** Если здесь напечаталось `Найдено окон: 0` —
дальше идти бессмысленно, надо понижать `BOX_THRESHOLD`. Если напечаталось 200 —
модель нашла всё подряд, порог надо поднимать.

# ЧАСТЬ 5. Проверка глазами

```python
import matplotlib.pyplot as plt
import matplotlib.patches as patches

fig, ax = plt.subplots(figsize=(11, 11))
ax.imshow(image)
for x0, y0, x1, y1 in boxes:
    ax.add_patch(patches.Rectangle((x0, y0), x1 - x0, y1 - y0,
                                   linewidth=1.6, edgecolor="lime", facecolor="none"))
ax.set_title(f"Grounding DINO: {len(boxes)} рамок")
ax.axis("off")
plt.show()
```

**`plt.subplots(figsize=(11, 11))`** создаёт холст 11×11 дюймов и возвращает два объекта:
`fig` (вся картинка целиком) и `ax` (область для рисования). Нам нужен `ax`.

**`ax.imshow(image)`** рисует фотографию как фон.

**`for x0, y0, x1, y1 in boxes:`** — цикл по строкам массива. На каждой итерации
берётся одна строка формы `(4,)`, и Python **автоматически распаковывает** её в четыре
переменные. Это называется unpacking и работает, потому что в строке ровно 4 числа.

**`patches.Rectangle((x0, y0), ширина, высота)`** — matplotlib рисует прямоугольник
по левому-верхнему углу и размерам, то есть в формате `xywh`. У нас `xyxy`. Перевод:
```
ширина = x1 - x0
высота = y1 - y0
```
Вот зачем в коде вычитания.

**`facecolor="none"`** — заливки нет, только контур. Иначе прямоугольники закрасили бы фото.

**Что смотреть на этой картинке:**
- рамок примерно столько же, сколько окон видно глазами → порог хороший;
- рамки на дверях, крышах, солнечных панелях, бассейне → порог поднять;
- половина окон без рамок → порог опустить;
- одна гигантская рамка на весь дом → модель поняла промпт как «здание», проверьте текст.

sam_processor = SamProcessor.from_pretrained(SAM_MODEL_ID)
sam_model = SamModel.from_pretrained(SAM_MODEL_ID).to(DEVICE).eval()

То же самое, что с Grounding DINO. Скачивается ~2.4 ГБ, это самый долгий шаг

## 6.2. Подготовка боксов — самое неочевидное место всего решения

```python
input_boxes = [[[float(v) for v in box] for box in boxes]]
```

Здесь **три** уровня вложенности квадратных скобок, и каждый нужен. Разбираем изнутри наружу.

**Уровень 1 (внутренний):** `[float(v) for v in box]`

Это *list comprehension* — сжатая запись цикла. Читается так: «для каждого `v` внутри
`box` вызови `float(v)` и собери в список».

Развёрнутая версия:
```python
result = []
for v in box:
    result.append(float(v))
```

`box` — одна строка массива, например `np.array([410.2, 220.7, 495.1, 330.4])`.
Результат — обычный питоновский список `[410.2, 220.7, 495.1, 330.4]`.

*Зачем `float(v)`.* Элементы numpy-массива имеют тип `np.float32`, а не встроенный
питоновский `float`. Процессор SAM в некоторых версиях спотыкается на numpy-типах.
Явное приведение убирает целый класс потенциальных ошибок.

**Уровень 2 (средний):** `[... for box in boxes]`

Проходим по всем строкам массива `boxes`. Получаем список списков — все боксы одной
картинки:
```python
[[410.2, 220.7, 495.1, 330.4],
 [612.0, 244.3, 690.8, 350.1],
 ...]
```

**Уровень 3 (внешний):** ещё одна пара `[ ... ]`

Это **батч картинок**. SAM спроектирован обрабатывать несколько картинок за раз,
и для каждой — свой набор боксов. У нас одна картинка, поэтому в батче один элемент.

Итоговая структура:
```
[                                   ← батч: список картинок
    [                               ← картинка №1: список её боксов
        [410.2, 220.7, 495.1, 330.4],   ← бокс №1: 4 числа
        [612.0, 244.3, 690.8, 350.1],   ← бокс №2
        ...
    ]
]
```

⚠️ **Самая частая ошибка здесь** — забыть внешний уровень и передать
`input_boxes=boxes.tolist()`. Тогда SAM решит, что каждый бокс — это отдельная картинка,
и либо упадёт, либо вернёт мусор.

## 6.3. Препроцессинг и прогон

```python
sam_inputs = sam_processor(image, input_boxes=input_boxes, return_tensors="pt").to(DEVICE)
```

Процессор SAM делает:
- масштабирует картинку так, чтобы длинная сторона стала 1024, и добивает до квадрата;
- нормализует пиксели;
- **пересчитывает координаты боксов** под новый масштаб (это важно — вы отдаёте боксы
  в координатах оригинала, а модель работает в своих; процессор берёт перевод на себя);
- запоминает исходные размеры, чтобы потом вернуть маски в оригинальном разрешении.

Что внутри `sam_inputs`:

```
pixel_values           (1, 3, 1024, 1024)   картинка
input_boxes            (1, N, 4)            боксы в координатах модели
original_sizes         (1, 2)               [[1024, 1024]] — исходный размер
reshaped_input_sizes   (1, 2)               [[1024, 1024]] — размер после ресайза
```

```python
with torch.no_grad():
    sam_outputs = sam_model(**sam_inputs, multimask_output=False)
```

**`multimask_output=False`** — «верни одну маску на промпт, а не три».

Напомню, почему SAM по умолчанию возвращает три: точка на пуговице неоднозначна
(пуговица? рубашка? человек?). Но **бокс — однозначный промпт**: если рамка обводит
окно, вариантов почти нет. Поэтому просим одну маску и не мучаемся с выбором лучшей.

**Форма `sam_outputs.pred_masks`: `(1, N, 1, 256, 256)`**
- `1` — батч картинок;
- `N` — число боксов;
- `1` — число масок на бокс (мы попросили одну);
- `256, 256` — маски выдаются в низком разрешении, это внутренний формат SAM.

## 6.4. Постобработка масок

```python
masks = sam_processor.image_processor.post_process_masks(
    sam_outputs.pred_masks.detach().cpu(),
    sam_inputs["original_sizes"].cpu(),
    sam_inputs["reshaped_input_sizes"].cpu(),
)[0]
```

Функция делает три вещи:
1. увеличивает маски с 256×256 до размера, в котором работала модель;
2. отрезает добивку (padding), которую добавили при приведении к квадрату;
3. масштабирует до **исходного** размера картинки и бинаризует по порогу 0.

Три аргумента — ровно то, что ей для этого нужно: сами маски, исходные размеры и
размеры после ресайза. Всё уже посчитано процессором, мы просто передаём это дальше.

**`[0]`** на конце — функция возвращает список (по элементу на картинку батча),
берём первый и единственный.

**Форма результата: `(N, 1, H, W)`**, тип — булев тензор PyTorch.

```python
masks = masks.squeeze(1).numpy().astype(bool)
print("Форма набора масок:", masks.shape)
```

**`.squeeze(1)`** — «убери ось номер 1, если её длина равна 1».
```
(N, 1, 1024, 1024)  →  (N, 1024, 1024)
```
Эта единица — рудимент режима трёх масок. Без неё дальнейшие операции пришлось бы
писать с лишней осью.

*Почему `squeeze(1)`, а не просто `squeeze()`.* Без аргумента `squeeze` убирает **все**
единичные оси. Если бы нашлось ровно одно окно, форма была бы `(1, 1, 1024, 1024)`,
и голый `squeeze()` схлопнул бы её в `(1024, 1024)` — потерялась бы ось количества масок,
и следующий шаг сломался бы. Указание конкретной оси защищает от этого.

**`.numpy()`** — из тензора PyTorch в массив numpy.
**`.astype(bool)`** — гарантируем тип «True/False», а не 0/1 числами.

**Итоговая форма: `(N, 1024, 1024)`** — N масок, каждая размером с фотографию.

# ЧАСТЬ 7. Склейка масок и сохранение ответа

```python
mask = np.any(masks, axis=0)
```

**`np.any(массив, axis=0)`** — «схлопни нулевую ось, поставив True там, где был хотя бы
один True».

Что происходит с формой:
```
(N, 1024, 1024)  →  (1024, 1024)
```

Механика: numpy идёт по каждой паре координат `(y, x)`, смотрит на все `N` значений
вдоль первой оси и ставит `True`, если хоть одно из них `True`.

Крошечный пример на двух масках 3×3:

```
masks[0]:        masks[1]:        np.any(masks, axis=0):
F  T  F          F  F  F          F  T  F
F  T  F          T  T  F     →    T  T  F
F  F  F          T  T  F          T  T  F
```

Обратите внимание на центральную клетку: она `True` в обеих масках. В результате
всё равно просто `True`. Пересечения окон обрабатываются сами собой.

⚠️ **Не делайте `masks.sum(axis=0)`.** Сумма даст `2` в пересечении, и после умножения
на 255 получится 510. Тип uint8 хранит числа только до 255, поэтому 510 «переполнится»
и превратится в 254 — визуально почти чёрную точку посреди белого окна. Если очень
хочется через сумму, пишите `masks.sum(axis=0) > 0`.

```python
print("Доля белых пикселей: %.2f%%" % (mask.mean() * 100))
```

**`mask.mean()`** для булева массива: numpy считает `True` за 1, `False` за 0, и берёт
среднее. Получается доля белых пикселей от 0 до 1. Умножаем на 100 → проценты.

**Это вторая контрольная точка.** Для фото с домами разумное значение — примерно
**2–10%**. Если 0.0% — маска пустая, что-то сломалось. Если 40% — модель засегментировала
дома целиком вместо окон, надо разбираться с промптом и порогом.

`%%` в строке форматирования — это способ напечатать один символ процента
(одиночный `%` matplotlib/Python воспримет как начало спецификатора).

```python
mask_uint8 = mask.astype(np.uint8) * 255
```

Два действия:

1. **`.astype(np.uint8)`** — тип `bool` превращается в `uint8`
   (*unsigned 8-bit integer* — целое без знака, диапазон 0…255).
   `True → 1`, `False → 0`.
2. **`* 255`** — умножаем весь массив на 255. `1 → 255`, `0 → 0`.

Почему именно uint8: это стандартный тип для картинок. Один пиксель — один байт.

⚠️ **Если забыть `* 255`**, в файле будут значения 0 и 1. Разница между яркостью 0 и
яркостью 1 глазом неразличима — вы увидите полностью чёрный квадрат и решите, что
модель ничего не нашла.

```python
mask_pil = Image.fromarray(mask_uint8)
mask_pil.save(OUTPUT_MASK_PATH)
```

**`Image.fromarray(...)`** — превращает numpy-массив в объект картинки PIL.
Массив формы `(H, W)` из uint8 интерпретируется как **градации серого**, режим `"L"`
(от англ. *luminance*). Это одноканальная чёрно-белая картинка — ровно то, что нужно.

Для сравнения: массив `(H, W, 3)` стал бы режимом `"RGB"`.

**`.save(OUTPUT_MASK_PATH)`** — записывает файл. Формат PIL определяет по расширению
имени: `.jpg` → JPEG.

> **Про JPEG и потерю качества.** JPEG сжимает с потерями, поэтому на границах белых
> областей появятся пиксели промежуточной яркости (например, 247 или 12). Это нормально
> и ожидаемо — проверяющая система бинаризует маску обратно по порогу. Формат `.jpg`
> явно указан в задании, поэтому его и используем.

```python
print("Сохранено:", OUTPUT_MASK_PATH, "| размер:", mask_pil.size, "| режим:", mask_pil.mode)
```

**Третья контрольная точка.** Тут должно быть напечатано:
- размер **ровно такой же**, как у исходного фото (у нас `(1024, 1024)`);
- режим `L`.

Если размер отличается — маска не совпадёт с эталоном ни при каких обстоятельствах.

# ЧАСТЬ 8. Финальная визуальная проверка

```python
overlay = np.array(image).astype(np.float32)
overlay[mask] = 0.45 * overlay[mask] + 0.55 * np.array([255.0, 40.0, 40.0])
```

**Строка 1.** `np.array(image)` превращает PIL-картинку в массив формы `(1024, 1024, 3)`
типа uint8. `.astype(np.float32)` переводит в дробные числа — чтобы при умножении на
0.45 не потерять точность из-за целочисленного деления.

**Строка 2** — самая красивая строчка в коде. Разбираем.

**`overlay[mask]`** — это *булева индексация*. `mask` имеет форму `(1024, 1024)`,
`overlay` — форму `(1024, 1024, 3)`. Numpy применяет маску к первым двум осям и
возвращает **все пиксели, где маска True**, в виде массива формы `(K, 3)`,
где `K` — количество белых пикселей.

Это не копия — это «вид» на исходный массив. Присваивание `overlay[mask] = ...`
записывает значения обратно ровно в те же позиции.

**`0.45 * overlay[mask] + 0.55 * np.array([255.0, 40.0, 40.0])`** — линейное смешивание
(*alpha blending*): 45% исходного цвета + 55% красного. Так окна становятся красными,
но сквозь них видно текстуру стекла — удобно проверять, что маска легла точно по контуру,
а не съехала.

`np.array([255.0, 40.0, 40.0])` имеет форму `(3,)`, а `overlay[mask]` — форму `(K, 3)`.
Numpy применяет **broadcasting**: маленький массив автоматически «размножается» вдоль
первой оси до формы `(K, 3)`. Писать цикл по пикселям не нужно.

```python
fig, axes = plt.subplots(1, 2, figsize=(16, 8))
axes[0].imshow(mask_uint8, cmap="gray")
axes[0].set_title("mask.jpg — это ответ")
axes[0].axis("off")
axes[1].imshow(overlay.astype(np.uint8))
axes[1].set_title("Проверка: окна подсвечены")
axes[1].axis("off")
plt.show()
```

**`plt.subplots(1, 2, ...)`** — «сетка из 1 строки и 2 столбцов». Возвращает массив
из двух областей рисования: `axes[0]` слева, `axes[1]` справа.

**`cmap="gray"`** — цветовая карта для одноканального массива. Без неё matplotlib
раскрасил бы маску в сине-жёлтый градиент (это его дефолт `viridis`) — неудобно смотреть.

**`.astype(np.uint8)`** обратно перед показом: matplotlib ждёт либо uint8 в диапазоне
0…255, либо float в диапазоне 0…1. Наш float лежит в 0…255, поэтому переводим в uint8.

**Что должно быть видно:** слева — чёрный квадрат с белыми прямоугольничками окон,
без единой подписи и рамки. Справа — фото, где красным подсвечены именно окна.
