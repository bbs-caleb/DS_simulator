# ЧАСТЬ 0. Что такое картинка для компьютера

Прежде чем говорить о сегментации, надо договориться, что вообще происходит внутри.

Цветная фотография для компьютера — это **трёхмерная таблица чисел**.

Возьмём наше фото домов размером 1024×1024 пикселя. Это:

```
1024 строки  ×  1024 столбца  ×  3 числа в каждой клетке
```

Три числа — это яркость красного, зелёного и синего (RGB), каждое от 0 до 255.
Пиксель `(255, 0, 0)` — чисто красный. `(0, 0, 0)` — чёрный. `(255, 255, 255)` — белый.

Итого в нашей картинке `1024 × 1024 × 3 = 3 145 728` чисел. Вот с этим массивом и
работают все модели компьютерного зрения.

Форму массива принято записывать в скобках: **`(1024, 1024, 3)`** — это называется
*shape* (форма). Дальше по тексту формы будут встречаться постоянно, и это самый
надёжный способ понимать, что происходит: если вы можете сказать, какой формы массив
на каждом шаге, вы понимаете код.

⚠️ **Ловушка, на которой спотыкаются все.** В библиотеке PIL размер картинки пишется
как `(ширина, высота)`, а в numpy форма массива — `(высота, ширина, каналы)`.
Порядок противоположный. Для квадратной картинки 1024×1024 разницы не видно, для
прямоугольной — видно сразу и больно. В коде решения из-за этого есть строка
`target_sizes=[(image.size[1], image.size[0])]` — там мы вручную переворачиваем порядок.

# ЧАСТЬ 1. Четыре разные задачи, которые все называют «компьютерное зрение»

Чтобы понимать, что делает SAM, нужно понимать, чего он **не** делает.

### 1.1. Классификация

**Вопрос:** что изображено на картинке?
**Ответ:** одно слово. `"дом"`.
**Форма ответа:** вектор вероятностей по классам, например `(1000,)` для 1000 классов.

Модель не знает, *где* на картинке дом. Она знает только, что он там есть.

### 1.2. Детекция (object detection)

**Вопрос:** какие объекты на картинке и где они?
**Ответ:** список прямоугольников с подписями.
```
окно, уверенность 0.87, прямоугольник (410, 220, 495, 330)
окно, уверенность 0.79, прямоугольник (612, 244, 690, 350)
дверь, уверенность 0.65, прямоугольник (500, 500, 560, 640)
```
**Форма ответа:** массив `(N, 4)` координат + массив `(N,)` уверенностей.

Прямоугольник называется **bounding box** («ограничивающая рамка»).

**Форматы боксов** — источник половины багов в CV. Их два основных:

| Формат | Что значат 4 числа | Пример |
|---|---|---|
| `xyxy` | x левого-верхнего, y левого-верхнего, x правого-нижнего, y правого-нижнего | `(410, 220, 495, 330)` |
| `xywh` | x левого-верхнего, y левого-верхнего, ширина, высота | `(410, 220, 85, 110)` |

Это **один и тот же прямоугольник**, записанный двумя способами. Если перепутать формат,
модель получит бессмысленные координаты и вернёт мусор без единой ошибки в консоли —
самый неприятный вид бага.

В нашем решении везде **xyxy**: и Grounding DINO отдаёт xyxy, и SAM ждёт xyxy. Повезло.

### 1.3. Сегментация

**Вопрос:** какие именно пиксели принадлежат объекту?
**Ответ:** маска — таблица того же размера, что картинка, где для каждого пикселя стоит
`True` (пиксель — часть объекта) или `False` (не часть).

**Форма ответа:** `(H, W)` = `(1024, 1024)` булевых значений.

Именно это и просят в задании. Маска, сохранённая в картинку: `True` → белый (255),
`False` → чёрный (0).

Виды сегментации, чтобы не путаться в терминах:

- **Семантическая (semantic):** все окна на картинке — одна общая маска. Модель не
  различает, где кончилось одно окно и началось другое.
- **Инстансная (instance):** каждое окно — своя отдельная маска. Пятнадцать окон —
  пятнадцать масок.
- **Паноптическая (panoptic):** и то и другое сразу плюс фон (небо, дорога, трава).

Наш пайплайн выдаёт **инстансные** маски (SAM возвращает отдельную маску на каждый бокс),
а мы их потом **сами склеиваем в семантическую** одной строчкой `np.any(masks, axis=0)`.
Это ровно то, что просит задание: одна маска на все окна.

### 1.4. Промптируемая сегментация (promptable segmentation) — то, что придумал SAM

**Вопрос:** какой объект я имею в виду вот этим указанием?
**Указание (промпт) может быть:**
- **точкой** — «объект, который в этом месте»;
- **несколькими точками** — «включая вот это, но не включая вот то»;
- **прямоугольником** — «объект внутри этой рамки»;
- **грубой маской** — «уточни вот эту приблизительную область»;
- **текстом** — «объект, описанный этими словами».

Это переформулировка задачи, которая всё изменила. Раньше модель сегментации обучали
под фиксированный список классов: «человек, машина, собака, велосипед…». Хотите
сегментировать окно — собирайте датасет окон и обучайте заново.

SAM обучен не «узнавать классы», а **отвечать на указание**. Ему всё равно, окно там
или космический корабль: он обучен на 1.1 миллиарда масок понимать, где у объекта
границы. Поэтому он работает на объектах, которых никогда не видел, — это и называется
**zero-shot** («ноль примеров»).

# ЧАСТЬ 2. Архитектура SAM — разбор картинки из задания

Картинка из статьи, которая приложена к уроку, читается слева направо. Разберём её
по блокам.

```
                                    ┌──────────────┐
 [картинка] ──► image encoder ──►   │              │
                (тяжёлый, ViT-H)    │ image        │
                                    │ embedding    │──┐
                                    │ 64×64×256    │  │
                                    └──────────────┘  │
                                                      ▼
 [промпт:                          ┌──────────────┐  ┌──────────────┐  ┌─────────┐
  точка / бокс / ──► prompt ──►    │ prompt       │──►│ mask decoder │──►│ 3 маски │
  маска / текст]     encoder       │ embeddings   │  │ (лёгкий)     │  │ + скоры │
                     (лёгкий)      └──────────────┘  └──────────────┘  └─────────┘
```

На оригинальной картинке из статьи: слева — фото с ножницами и рамка (это два промпта),
в середине — «квадратики» (эмбеддинг картинки), значок мишени (промпт-энкодер),
трапеция `Conv` (свёртка для маски-промпта), прямоугольник `Prompt encoder`,
красный прямоугольник `Mask decoder`, справа — три варианта результата.

Теперь по блокам подробно.

## 2.1. Image encoder — самая тяжёлая часть

**Что делает:** превращает картинку `(1024, 1024, 3)` в компактное «сжатое понимание»
формы `(64, 64, 256)`.

**Как читать эту форму.** Картинку разрезали на сетку 64×64 квадратиков (каждый
квадратик — участок 16×16 пикселей исходника). Для каждого квадратика посчитали
256 чисел, описывающих, что там: текстура, край, часть чего это может быть, как это
связано с остальной картинкой. Эти 256 чисел называются **эмбеддингом** — вектором
смысла кусочка изображения.

**Чем делает:** Vision Transformer (ViT-H — «huge», самая большая версия, ~630 млн
параметров). ViT — это трансформер, тот же тип архитектуры, что в языковых моделях,
только вместо слов на вход идут кусочки картинки (patches). Каждый кусочек «смотрит»
на все остальные через механизм внимания (attention) — поэтому модель понимает не
только «здесь стекло», но и «здесь стекло в прямоугольной раме на кирпичной стене»,
то есть контекст.

**Предобучение:** MAE (Masked Autoencoder) — модели закрывали 75% картинки и заставляли
восстанавливать. Так она научилась понимать структуру объектов до того, как увидела
хоть одну маску.

**Цена:** ~0.15 секунды на GPU A100, несколько секунд на CPU. Это 99% всей вычислительной
стоимости SAM.

**Ключевое свойство, которое надо запомнить:** энкодер работает **один раз на картинку**.
Дальше можно задавать сколько угодно промптов — он больше не запускается. Это архитектурное
решение и есть причина, по которой демо SAM в браузере отвечает мгновенно: тяжёлая часть
уже посчитана на сервере, а в браузер уехал только эмбеддинг 64×64×256 (~4 МБ).

## 2.2. Prompt encoder — переводчик указаний в язык модели

**Что делает:** превращает промпт в векторы той же «размерности смысла» (256), что и
кусочки картинки, — чтобы декодер мог их сопоставлять.

Промпты делятся на два типа:

**Разреженные (sparse)** — точки, боксы, текст:
- **Точка** → позиционное кодирование координат (x, y) + обучаемый вектор «я передний
  план» или «я фон». Итого один вектор длины 256.
- **Бокс** → представляется как **две точки**: левый-верхний угол и правый-нижний угол,
  каждая со своим обучаемым вектором «я угол такой-то». Итого два вектора по 256.
  Именно так наш бокс окна попадает внутрь SAM.
- **Текст** → энкодер текста из CLIP. *(В открытых весах SAM этот путь фактически не
  используется — и именно поэтому в задании мы берём Grounding DINO. Об этом ниже.)*

**Плотные (dense)** — грубая маска:
- проходит через несколько свёрток (та самая трапеция `Conv` на картинке) и складывается
  напрямую с эмбеддингом картинки.

## 2.3. Mask decoder — лёгкий, быстрый, хитрый

**Что делает:** берёт эмбеддинг картинки + эмбеддинги промпта и выдаёт маски.

**Внутри:** всего два слоя трансформера, но с необычной схемой внимания — внимание
работает **в обе стороны**:

1. **Self-attention по токенам промпта** — промпты «договариваются» между собой
   (если точек несколько).
2. **Cross-attention промпт → картинка** — промпт «смотрит» на картинку: где искать?
3. Обновление эмбеддинга картинки через MLP.
4. **Cross-attention картинка → промпт** — картинка «смотрит» на промпт: что от меня хотят?

Этот цикл повторяется дважды. Затем эмбеддинг картинки увеличивается обратно
(64×64 → 256×256) транспонированными свёртками, а специальные выходные токены через
маленький MLP превращаются в «фильтр», который скалярно перемножается с картой признаков.
Результат — карта вероятностей, где каждый пиксель имеет число «насколько я часть объекта».

**Порог 0.0** (это логит, не вероятность) отделяет объект от фона → получается булева маска.

**Цена:** ~50 миллисекунд на CPU. В 100+ раз дешевле энкодера.

## 2.4. Три маски и IoU-скор — решение проблемы неоднозначности

Поставьте точку на пуговице рубашки человека. Что вы имели в виду?
- пуговицу,
- рубашку,
- человека целиком.

Промпт принципиально неоднозначен. Поэтому SAM по умолчанию выдаёт **три маски** —
примерно соответствующие уровням «часть объекта / объект / целое», и для каждой
предсказывает **свой ожидаемый IoU** (насколько, по мнению модели, эта маска хороша).
Дальше можно выбрать маску с максимальным скором.

Это на картинке справа: три варианта результата с ножницами.

**В нашей задаче** мы ставим `multimask_output=False` и получаем одну маску на бокс.
Почему так можно: бокс — гораздо более однозначный промпт, чем точка. Если рамка обводит
окно, вариантов «что имелось в виду» практически нет.

## 2.5. Как SAM обучали: data engine

Чтобы модель работала zero-shot, нужен гигантский датасет. Ни одного датасета на
миллиард масок не существовало, поэтому Meta построила его сама, в три стадии
(это любимый вопрос на собеседовании):

1. **Assisted-manual.** Разметчики кликают, слабая версия SAM предлагает маску, человек
   поправляет. Модель дообучается на результате и становится лучше → разметчики работают
   быстрее. Собрано ~4.3 млн масок.
2. **Semi-automatic.** Модель сама размечает то, в чём уверена; людям отдают только
   то, что модель пропустила. Растёт разнообразие. Собрано ~10.2 млн масок.
3. **Fully automatic.** Модель покрывает картинку сеткой из 32×32 точек-промптов и
   размечает всё сама, слабые маски отфильтровываются по скору и стабильности.
   Собрано **1.1 млрд масок на 11 млн изображений** — датасет SA-1B.

**Функция потерь при обучении:** комбинация focal loss и dice loss в пропорции 20:1.
Focal — чтобы модель не «сдавалась» на редких трудных пикселях границы; dice — чтобы
следила за формой маски целиком.

# ЧАСТЬ 3. SAM 2 — что изменилось

В библиотеке `lang-segment-anything`, которую приложили к уроку, внутри уже **SAM 2.1**.
Отличия от SAM 1, коротко:

| | SAM 1 | SAM 2 |
|---|---|---|
| Энкодер картинки | ViT-H | **Hiera** (иерархический ViT, признаки на нескольких масштабах) |
| Что умеет | изображения | изображения **и видео** |
| Новое в архитектуре | — | **memory attention**: помнит объект между кадрами |
| Скорость | базовая | ~6× быстрее на изображениях |
| Размеры | vit_b / vit_l / vit_h | tiny / small / base+ / large |

Для нашей задачи (одна статичная картинка) разница в качестве масок окон невелика —
границы окон простые и прямые, обе версии справляются. В решении используется **SAM 1
(`facebook/sam-vit-huge`)**, потому что:

- урок и приложенный ноутбук `predictor_example.ipynb` — про SAM 1;
- картинка архитектуры в задании — это SAM 1;
- SAM 1 в библиотеке `transformers` ставится в одну строку и не тянет за собой
  hydra, omegaconf и сборку CUDA-расширений, на которых регулярно ломается установка
  `lang-segment-anything` в Colab.

Это осознанный размен: минус экзотика, плюс воспроизводимость.

# ЧАСТЬ 4. Проблема: SAM не понимает слова

Вот главный сюжетный поворот урока.

В статье SAM текстовые промпты **заявлены**, но в опубликованных весах и официальной
библиотеке `segment-anything` **их нет**. Проверить легко: в `SamPredictor.predict()`
есть аргументы `point_coords`, `point_labels`, `box`, `mask_input` — и ни одного про текст.

Именно поэтому в задании написано: *«официальная библиотека SAM не поддерживает их
напрямую»*. Это не ограничение вашего кода, это факт про модель.

**Обходной манёвр** (он же — стандартная индустриальная практика под названием
**Grounded-SAM**):

```
текст "window."
      │
      ▼
┌─────────────────┐   боксы    ┌──────────┐   маски
│ Grounding DINO  │ ─────────► │   SAM    │ ─────────►  результат
│ понимает слова  │  (N, 4)    │ рисует   │  (N, H, W)
│ но рисует рамки │            │ контуры  │
└─────────────────┘            └──────────┘
```

Разделение труда: одна модель понимает язык, вторая понимает границы объектов.
Каждая делает то, что умеет лучше всех.

# ЧАСТЬ 5. Grounding DINO — модель, которая понимает текст

**Задача, которую решает:** open-set detection, то есть детекция объектов **произвольных
классов, заданных словами**. Обычный детектор (YOLO, обученный на COCO) знает ровно 80
классов и не найдёт «солнечную панель», потому что такого класса в его списке нет.
Grounding DINO найдёт всё, что вы напишете словами.

**Как устроен (по-простому):**

1. **Два энкодера.** Картинка идёт через Swin Transformer, текст — через BERT.
   Получаются два набора векторов: «признаки картинки» и «признаки слов».
2. **Feature enhancer.** Признаки картинки и текста многократно «смотрят» друг на друга
   через cross-attention. Здесь происходит главное: вектор кусочка картинки со стеклом
   в раме подтягивается ближе к вектору слова `window`.
3. **Language-guided query selection.** Из тысяч кандидатных областей картинки
   отбираются те, что сильнее всего похожи на слова промпта.
4. **Cross-modality decoder.** Отобранные кандидаты уточняются и превращаются в
   финальные координаты боксов + оценки соответствия каждому слову промпта.

**Почему промпт должен заканчиваться точкой.**
Grounding DINO обучался на промптах вида `"cat. dog. person."` — точка работает как
разделитель классов. Если написать `"window"` без точки, модель формально отработает,
но это выход за пределы формата обучающих данных, и качество может просесть.
Библиотека `lang-segment-anything` добавляет точку автоматически:

```python
texts_prompt = [prompt if prompt[-1] == "." else prompt + "." for prompt in texts_prompt]
```

Мы просто сразу пишем `"window."` и не полагаемся на автодобавление.

## 5.1. Два порога — самая важная настройка во всём решении

```python
BOX_THRESHOLD = 0.30
TEXT_THRESHOLD = 0.25
```

Это не одно и то же, и путать их нельзя.

**`box_threshold` — «насколько модель вообще уверена, что тут объект».**
Каждый кандидатный бокс имеет скор от 0 до 1. Боксы со скором ниже порога выбрасываются.

| Значение | Что происходит | Риск |
|---|---|---|
| 0.15 | находится очень много всего | в маску попадут двери, панели, куски крыши |
| 0.25–0.30 | баланс, значение по умолчанию | — |
| 0.40+ | только самые очевидные окна | половина окон потеряется |

**`text_threshold` — «какие слова промпта относятся к найденному боксу».**
Работает внутри промпта. Если промпт `"window. door. roof."`, для каждого бокса
модель считает соответствие каждому слову, и слова со скором ниже `text_threshold`
не приписываются боксу. При промпте из одного слова этот порог почти ни на что не влияет.

**Практический вывод:** для этой задачи крутить надо `box_threshold`, а `text_threshold`
оставить 0.25.

# ЧАСТЬ 6. Как боксы превращаются в маски и почему их надо склеивать

## 6.1. Что возвращает SAM

Для `N` боксов и картинки `H×W` SAM с `multimask_output=False` возвращает тензор формы:

```
(N, 1, H, W)
 │  │  │  └── ширина
 │  │  └───── высота
 │  └──────── число масок на один промпт (мы попросили одну)
 └─────────── число промптов = число боксов
```

Единица посередине — рудимент режима «три маски». Убираем её:

```python
masks = masks.squeeze(1)     # (N, 1, H, W) → (N, H, W)
```

Теперь `masks[0]` — маска первого окна, `masks[1]` — второго и так далее.
Каждая маска — таблица `1024×1024` из `True`/`False`.

## 6.2. Склейка: логическое ИЛИ по всем маскам

Задание просит **одну** маску на все окна. Значит, пиксель должен стать белым, если он
принадлежит **хотя бы одному** окну:

```python
mask = np.any(masks, axis=0)      # (N, H, W) → (H, W)
```

`axis=0` — «схлопни первую ось». Для каждой пары координат `(y, x)` numpy проходит по
всем `N` маскам и ставит `True`, если хоть где-то был `True`.

Мини-пример на картинке 3×3 и двух масках:

```
маска 0:            маска 1:            np.any(..., axis=0):
F  T  F             F  F  F             F  T  F
F  T  F             T  T  F      →      T  T  F
F  F  F             T  T  F             T  T  F
```

Пересечения (пиксель попал в две маски) обрабатываются автоматически — `True or True`
это всё тот же `True`. Никакого «двойного» белого не бывает.

**Почему нельзя `masks.sum(axis=0)`:** сумма даст 2 там, где маски пересеклись, и потом
`* 255` превратит это в 510, что при записи в uint8 переполнится и станет 254 — то есть
почти чёрный пиксель посреди белого окна. Классическая ошибка. Если очень хочется через
сумму — только так: `masks.sum(axis=0) > 0`.

## 6.3. Превращение в картинку

```python
mask_uint8 = mask.astype(np.uint8) * 255
```

- `mask` содержит `True`/`False`.
- `.astype(np.uint8)` превращает их в `1`/`0` (тип uint8 — целое число от 0 до 255,
  ровно то, что понимает формат картинки).
- `* 255` растягивает `1` → `255` (белый), `0` остаётся `0` (чёрный).

```python
Image.fromarray(mask_uint8)
```
Массив `(H, W)` из uint8 PIL интерпретирует как **градации серого** — режим `"L"`.
Это одноканальная чёрно-белая картинка. Ровно то, что требуется.

⚠️ Если пропустить `* 255`, получится картинка со значениями 0 и 1 — визуально
полностью чёрная, потому что 1 из 255 глазом неотличима от 0. Проверяющая система,
скорее всего, тоже сочтёт её пустой.

# ЧАСТЬ 7. Как оценивают качество маски

## 7.1. IoU — Intersection over Union

Основная метрика сегментации и детекции:

```
        площадь пересечения (моя маска ∩ эталон)
IoU = ───────────────────────────────────────────
        площадь объединения (моя маска ∪ эталон)
```

- Полное совпадение → IoU = 1.0
- Нет пересечения вообще → IoU = 0.0
- Обычный «хороший» результат сегментации → 0.85–0.95

```python
intersection = (pred & true).sum()
union = (pred | true).sum()
iou = intersection / union
```

## 7.2. Dice (F1 для пикселей)

```
Dice = 2 × |пересечение| / (|моя маска| + |эталон|)
```
Всегда чуть выше IoU при том же результате. Популярен в медицинской сегментации.

## 7.3. Pixel accuracy — и почему ей нельзя верить

```
accuracy = доля пикселей, где я угадал (объект/фон)
```

Ловушка: если окна занимают 5% кадра, то маска, состоящая **целиком из чёрного**,
даёт accuracy 95%. Метрика выглядит отлично, модель не делает вообще ничего.
Это называется **проблемой дисбаланса классов**, и на собеседовании умение назвать
эту ловушку ценится выше, чем знание формулы IoU.

# ЧАСТЬ 9. Мини-словарь терминов урока

| Термин | Перевод на человеческий |
|---|---|
| **SAM** | Segment Anything Model — модель Meta, сегментирующая что угодно по указанию |
| **Промпт (prompt)** | указание модели, что именно сегментировать: точка, рамка, маска или текст |
| **Zero-shot** | модель решает задачу, ни одного примера которой не видела при обучении |
| **Эмбеддинг** | вектор чисел, кодирующий смысл объекта (кусочка картинки, слова) |
| **Image encoder** | часть модели, сжимающая картинку в эмбеддинг. Тяжёлая, работает один раз |
| **Mask decoder** | часть модели, рисующая маску по эмбеддингу и промпту. Лёгкая и быстрая |
| **Bounding box** | прямоугольник вокруг объекта, 4 числа |
| **xyxy** | формат бокса: левый-верхний угол и правый-нижний угол |
| **Маска** | таблица True/False размером с картинку: где объект, а где нет |
| **Логит** | «сырое» число до превращения в вероятность; порог для маски — 0.0 |
| **IoU** | пересечение / объединение — насколько маска совпала с эталоном |
| **Grounding DINO** | детектор, находящий объекты по текстовому описанию |
| **Grounded-SAM** | связка «Grounding DINO → SAM»: текст → рамки → маски |
| **ViT** | Vision Transformer — трансформер, работающий с кусочками картинки |
| **Hiera** | иерархический ViT, энкодер внутри SAM 2 |
| **SA-1B** | датасет SAM: 11 млн картинок, 1.1 млрд масок |

# ЧАСТЬ 10. Что нужно унести из этого файла в голове

1. Сегментация ≠ детекция. Детекция даёт рамку, сегментация — пиксели.
2. SAM обучен не классам, а **умению находить границы по указанию**. Отсюда zero-shot.
3. Архитектура SAM асимметрична: **тяжёлый энкодер один раз, лёгкий декодер много раз**.
   Это объясняет и скорость демо, и то, как надо проектировать сервис в проде.
4. SAM **не понимает текст** в открытых весах. Текст понимает Grounding DINO,
   который отдаёт SAM рамки. Это и есть Grounded-SAM.
5. `box_threshold` — главная ручка качества. Ниже порог — больше находок и больше мусора.
6. Маски склеиваются логическим ИЛИ (`np.any`), а не суммой.
7. Финальная маска — строго два значения: 0 и 255, размер ровно как у исходного фото.
