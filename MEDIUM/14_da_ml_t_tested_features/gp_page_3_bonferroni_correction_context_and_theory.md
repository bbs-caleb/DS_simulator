# Page 3 — поправка Бонферрони: контекст и теория

## 1. Где мы находимся в цепочке урока

К этому шагу уже есть две версии отбора признаков.

### Page 1 — базовый SFS

На каждой итерации мы:

1. добавляли к текущему набору каждый оставшийся признак;
2. считали средний CV `R²`;
3. выбирали кандидата с максимальным средним качеством;
4. прекращали отбор, когда среднее качество больше не росло.

### Page 2 — T-Tested SFS

Мы перестали доверять только среднему значению.

Для каждого кандидата стали сравнивать два массива оценок:

```text
current_scores
candidate_scores
```

через односторонний парный t-тест:

```python
ttest_rel(
    candidate_scores,
    current_scores,
    alternative="greater",
)
```

Признак допускался к выбору только при:

```python
p_value < alpha
```

### Page 3 — Bonferroni SFS

Теперь учитывается ещё одна проблема:

```text
на каждой итерации проверяется сразу много гипотез
```

Если оставить порог `0.05` для каждой отдельной проверки, вероятность хотя бы одного случайного значимого результата становится намного выше 5%.

---

# 2. Что такое множественное тестирование

Представим, что у нас 50 полностью бесполезных признаков.

Для каждого признака проверяется гипотеза:

```text
H0: добавление признака не улучшает модель
H1: добавление признака улучшает модель
```

При:

```python
alpha = 0.05
```

мы допускаем примерно 5% риск ошибки I рода для одной проверки.

Ошибка I рода означает:

```text
мы решили, что эффект есть,
хотя в действительности эффекта нет
```

Но SFS выполняет не одну проверку.

На первой итерации может быть:

```text
50 тестов
```

На второй:

```text
49 тестов
```

На третьей:

```text
48 тестов
```

И так далее.

Даже когда каждый отдельный тест контролируется на уровне 5%, вся группа тестов уже не контролируется на уровне 5%.

---

# 3. Почему вероятность ложного открытия растёт

Пусть вероятность не совершить ошибку в одном независимом тесте:

```text
1 - 0.05 = 0.95
```

Для 10 тестов вероятность не получить ни одного ложноположительного результата примерно:

```text
0.95^10 ≈ 0.599
```

Вероятность получить хотя бы один ложноположительный результат:

```text
1 - 0.95^10 ≈ 0.401
```

То есть около 40%.

Для 50 тестов:

```text
1 - 0.95^50 ≈ 0.923
```

Это уже около 92%.

Эта формула опирается на упрощённое предположение независимости тестов. В SFS тесты не полностью независимы, но основная проблема остаётся: большое количество сравнений раздувает риск ложных открытий.

---

# 4. Что контролирует поправка Бонферрони

Поправка Бонферрони направлена на контроль:

```text
FWER — Family-Wise Error Rate
```

Это вероятность совершить хотя бы одну ошибку I рода внутри семейства гипотез.

Для семейства из `m` тестов используется порог:

```text
corrected_alpha = alpha / m
```

Пример:

```text
alpha = 0.05
m = 10

corrected_alpha = 0.05 / 10 = 0.005
```

Теперь отдельный кандидат проходит только при:

```python
p_value < 0.005
```

---

# 5. Почему порог меняется на каждой итерации

Это ключевой момент задания.

В начале:

```text
excluded_features = 50
```

Следовательно:

```text
corrected_alpha = 0.05 / 50 = 0.001
```

После выбора одного признака:

```text
excluded_features = 49
```

Новый порог:

```text
corrected_alpha = 0.05 / 49 ≈ 0.0010204
```

После выбора ещё одного:

```text
corrected_alpha = 0.05 / 48 ≈ 0.0010417
```

То есть поправку нельзя один раз вычислить перед всем алгоритмом.

Она должна рассчитываться внутри внешнего цикла:

```python
for ...:
    corrected_alpha = (
        self.alpha / len(excluded_features)
    )
```

# 6. Точный бизнесовый смысл

Поправка Бонферрони делает отбор более консервативным.

Она отвечает на вопрос:

> Достаточно ли сильно этот признак улучшает модель, чтобы выдержать тот факт, что мы одновременно перебрали десятки альтернатив?

Это полезно, когда ложное включение признака дорого.

# 7. Применение в финтехе

## Антифрод

Пусть есть 300 потенциальных признаков:

- поведение устройства;
- IP-сигналы;
- геолокация;
- velocity features;
- история платежей;
- fingerprint;
- merchant features.

Если проверять каждый при `alpha=0.05`, часть шумовых сигналов почти неизбежно окажется «значимой».

Цена ошибки:

- лишние false positive;
- блокировка честных клиентов;
- увеличение ручных проверок;
- стоимость внешних API;
- сложный мониторинг;
- потенциальные regulatory issues.

Bonferroni снижает вероятность включить случайно значимый сигнал.

# 8. Кредитный скоринг

При скоринге могут проверяться:

- device features;
- поведенческие данные;

- потребовать дорогой источник данных.

Консервативный отбор особенно полезен, когда модель регулируемая и должна быть объяснима.

# 9. Маркетплейсы и e-commerce

# 14. Как меняется API

В конструктор добавляется:

```python
bonferroni: bool = True
```

Объект обязан сохранять:

```python
self.bonferroni = bonferroni
```

Если:

```python
bonferroni=True
```

используется:

```python
corrected_alpha = (
    self.alpha / len(excluded_features)
)
```

Если:

```python
bonferroni=False
```

используется обычный порог:

```python
corrected_alpha = self.alpha
```

Таким образом один класс поддерживает оба режима:

```text
обычный t-tested SFS
Bonferroni t-tested SFS
```

# 15. Почему делим на число исключённых признаков

На текущей итерации гипотеза проверяется для каждого признака из:

```python
excluded_features
```

Именно число этих кандидатов является размером текущего семейства тестов.

Неправильно делить всегда на:

```python
self.n_features_
```

Потому что после каждого выбора число гипотез уменьшается.

Неправильно делить на:

```python
self.max_features
```

Потому что `max_features` — число возможных шагов отбора, а не число одновременно тестируемых кандидатов.

# 16. Полный алгоритм page_3

```text
1. included = []
2. excluded = все признаки
3. current_scores = CV scores DummyRegressor

4. Сделать не более max_features итераций:

   4.1. m = len(excluded)

   4.2. Если bonferroni=True:
            threshold = alpha / m
        иначе:
            threshold = alpha

   4.3. Для каждого candidate в excluded:

        subset = included + candidate

        candidate_scores =
            CV scores модели на subset

        p_value =
            paired one-sided t-test(
                candidate_scores,
                current_scores
            )

        если p_value < threshold:
            кандидат считается допустимым

   4.4. Если допустимых нет:
        остановиться

   4.5. Среди допустимых выбрать
        максимальный mean R²

   4.6. Добавить победителя

   4.7. Удалить победителя из excluded

   4.8. current_scores = scores победителя

5. Отсортировать выбранные индексы
```

# 17. Почему Bonferroni считается консервативной

Поправка хорошо контролирует вероятность хотя бы одной ложной находки, но может быть слишком строгой.

Следствие:

- меньше false positives;
- больше false negatives;
- слабый, но реальный признак может не пройти.

Это компромисс.

Bonferroni особенно оправдана, когда ошибка ложного включения признака дороже, чем пропуск слабого признака.

---

# 18. Bonferroni и FDR — не одно и то же

Bonferroni контролирует:

```text
вероятность хотя бы одной ошибки
```

Методы вроде Benjamini–Hochberg контролируют:

```text
ожидаемую долю ложных открытий
среди всех открытий
```

Bonferroni строже.

В текущем задании требуется именно Bonferroni.

---

# 19. Важное ограничение

Поправка Бонферрони не решает:

- target leakage;
- неправильную CV;
- временную утечку;
- dataset shift;
- плохую бизнес-метрику;
- нестабильность между сегментами;
- bias и fairness;
- data quality.

Она решает только проблему раздувания ошибки I рода из-за множества статистических проверок.
