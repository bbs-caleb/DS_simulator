# SequentialForwardSelector — page_1: максимально подробное объяснение базового SFS

## 0. Главное исправление относительно первой неудачной версии

Первая версия всегда добавляла ровно `max_features` колонок. Это нарушало смысл слова «maximum» и приводило к выбору шумовых признаков после того, как качество переставало расти.

Исправленная версия хранит `current_score` и прекращает отбор при условии:

```python
best_score <= current_score
```

Ниже весь код разобран уже с правильной логикой.

## 1. Что требуется от класса

Автопроверка ожидает конкретный публичный интерфейс.

```python
X_selected = selector.transform(X)
```

```python
selector.n_features_
```

Имена должны совпадать буквально. В API автотесты часто проверяют не только результат, но и наличие точных методов и атрибутов.

## 2. Полный алгоритм человеческим языком

Пусть `X` содержит четыре колонки с индексами:

```text
0, 1, 2, 3
```

Нужно выбрать две.

Сначала:

```python
selected_features_ = []
excluded_features = [0, 1, 2, 3]
```

На первой итерации код сравнивает:

```text
[0]
[1]
[2]
[3]
```

Предположим, лучший `R²` получен на `[2]`.

После этого:

```python
selected_features_ = [2]
excluded_features = [0, 1, 3]
```

На второй итерации сравниваются:

```text
[2, 0]
[2, 1]
[2, 3]
```

Пусть выигрывает `[2, 1]`.

До сортировки выбор хранится как порядок принятия решений:

```python
[2, 1]
```

Но условие описывает `selected_features_` как список, упорядоченный по индексу, поэтому в конце вызывается:

```python
self.selected_features_.sort()
```

И финальный результат:

```python
[1, 2]
```

## 4. Конструктор `__init__`

```python
def __init__(
    self,
    model,
    cv,
    max_features: int = 10,
    verbose: int = 0,
) -> None:
```

### Что такое `self`

`self` — конкретный созданный объект.

Когда пишем:

```python
selector = SequentialForwardSelector(model, cv, 10)
```

Python создаёт объект и передаёт его в `__init__` как `self`.

### Сохранение входных параметров

```python
self.model = model
self.cv = cv
self.max_features = max_features
self.verbose = verbose
```

После этого параметры доступны в других методах:

```python
self.model
self.cv
```

Без сохранения `fit` не знал бы, какую модель и схему валидации использовать.

### Инициализация обучаемых атрибутов

```python
self.n_features_ = 0
self.selected_features_ = []
```

До вызова `fit` класс ещё ничего не выбрал.

Почему имена заканчиваются подчёркиванием?

В scikit-learn это соглашение: атрибут с `_` в конце появляется или получает осмысленное значение после обучения/fit.

## 5. Метод `fit`

### Сигнатура

```python
def fit(self, X: np.ndarray, y: np.ndarray) -> None:
```

- `X` — матрица признаков формы `(число_строк, число_колонок)`;
- `y` — целевая переменная длины `число_строк`.

Например:

```text
X.shape = (10000, 50)
y.shape = (10000,)
```

### Запоминаем исходное число признаков

```python
self.n_features_ = X.shape[1]
```

`X.shape[0]` — число строк.

`X.shape[1]` — число колонок.

Для задания:

```python
self.n_features_ = 50
```

### Сбрасываем прошлый результат

```python
self.selected_features_ = []
```

Это важно, если пользователь вызовет `fit` второй раз на другом датасете. Старые признаки не должны остаться.

### Создаём список ещё не выбранных признаков

```python
excluded_features = list(range(self.n_features_))
```

При 5 колонках:

```python
range(5)
```

описывает числа от 0 до 4, а `list` превращает их в список:

```python
[0, 1, 2, 3, 4]
```

### Определяем число итераций

```python
features_to_select = min(self.max_features, self.n_features_)
```

Почему используется `min`?

Если в данных 5 колонок, но случайно передали `max_features=10`, нельзя выбрать 10 разных колонок. Без ограничения на шестой итерации список кандидатов станет пустым.

Поэтому:

```text
min(10, 5) = 5
```

Класс выберет все доступные пять и не упадёт.

### Начальное качество текущего набора

```python
current_score = float("-inf")
```

`current_score` хранит средний CV `R²` уже выбранного набора.

В начале набор пустой. Оценивать линейную регрессию на матрице без колонок в рамках этого задания не нужно, поэтому используется отрицательная бесконечность.

Это гарантирует, что первый лучший одиночный признак сможет пройти проверку улучшения.

### Внешний цикл

```python
for step in range(features_to_select):
```

Одна итерация внешнего цикла — попытка выбрать один новый признак.

Если `features_to_select = 10`, цикл может выполниться максимум 10 раз. Он способен завершиться раньше через `break`, когда лучший оставшийся кандидат уже не повышает качество.

### Словарь оценок кандидатов

```python
candidate_scores = {}
```

На каждой итерации создаётся новый словарь вида:

```python
{
    0: 0.58,
    1: 0.66,
    3: 0.61,
}
```

Ключ — индекс кандидата.

Значение — его средний CV `R²` вместе с уже выбранными признаками.

### Внутренний цикл по кандидатам

```python
for candidate in excluded_features:
```

Код по очереди проверяет каждую ещё не выбранную колонку.

### Формирование временного набора

```python
feature_subset = self.selected_features_ + [candidate]
```

Если уже выбраны `[2, 5]`, а кандидат равен `7`, получим:

```python
[2, 5] + [7] == [2, 5, 7]
```

Почему кандидат оборачивается в список `[candidate]`?

Потому что складывать можно список со списком. Запись `list + int` вызвала бы ошибку.

### Выбор колонок NumPy

```python
X[:, feature_subset]
```

Разберём синтаксис:

- до запятой `:` означает взять все строки;
- после запятой `feature_subset` означает взять только указанные колонки.

Если `feature_subset = [2, 5, 7]`, результат содержит все наблюдения, но только три колонки.

### Кросс-валидация

```python
scores = cross_val_score(
    self.model,
    X[:, feature_subset],
    y,
    scoring="r2",
    cv=self.cv,
    n_jobs=-1,
)
```

Разберём аргументы.

#### `self.model`

Estimator, переданный в конструктор. В условии это `LinearRegression()`.

#### `X[:, feature_subset]`

Только текущий кандидатный набор признаков.

#### `y`

Целевая переменная.

#### `scoring="r2"`

Метрика из условия.

#### `cv=self.cv`

Используется схема `RepeatedKFold`, переданная снаружи.

Класс не создаёт новую CV сам. Это правильно, потому что пользователь контролирует валидацию.

#### `n_jobs=-1`

Scikit-learn может использовать все доступные CPU-ядра для фолдов.

### Что хранится в `scores`

При `3 × 10` в массиве 30 чисел:

```python
scores.shape == (30,)
```

Например:

```text
[0.61, 0.63, 0.60, ..., 0.62]
```

### Средняя оценка кандидата

```python
candidate_scores[candidate] = scores.mean()
```

Алгоритму нужно одно число для ранжирования кандидатов. Используется среднее 30 значений.

### Поиск лучшего кандидата

```python
best_feature = max(
    candidate_scores,
    key=lambda feature: candidate_scores[feature],
)
```

По умолчанию `max(dictionary)` сравнивал бы ключи, то есть индексы колонок. Нам нужно сравнивать значения `R²`.

`key=lambda feature: candidate_scores[feature]` говорит:

> Для каждого индекса посмотри его score и выбери индекс с максимальным score.

Пример:

```python
candidate_scores = {0: 0.58, 1: 0.66, 3: 0.61}
```

Результат:

```python
best_feature == 1
```

### Сохраняем лучший score

```python
best_score = candidate_scores[best_feature]
```

Это качество набора:

```python
self.selected_features_ + [best_feature]
```

Оно используется не только для вывода, но и для главного условия остановки.

### Проверяем реальное улучшение

```python
if self.selected_features_ and best_score <= current_score:
    if self.verbose > 0:
        print("No feature improves the score. Selection stopped.")
    break
```

Разберём условие по частям.

#### `self.selected_features_`

Пустой список трактуется как `False`, непустой — как `True`.

Проверка нужна, чтобы на первой итерации обязательно выбрать лучший одиночный признак. У пустого набора в текущей реализации нет рассчитанного CV score.

#### `best_score <= current_score`

Если даже лучший оставшийся кандидат:

- дал меньший score;
- или дал точно такой же score,

он не улучшает модель.

Тогда добавлять его нельзя. Признак увеличит сложность, но не даст дополнительного качества.

#### `break`

`break` немедленно завершает внешний цикл.

Именно поэтому итоговое число признаков может быть меньше `max_features`.

### Добавляем признак в выбранные

```python
self.selected_features_.append(best_feature)
```

Эта строка выполняется только после того, как кандидат прошёл проверку улучшения.

### Удаляем его из кандидатов

```python
excluded_features.remove(best_feature)
```

Один и тот же признак нельзя выбрать повторно.

### Обновляем качество текущего набора

```python
current_score = best_score
```

На следующей итерации новый кандидат будет сравниваться уже с качеством обновлённого набора.

### Вывод прогресса

```python
if self.verbose > 0:
    print(...)
```

При `verbose=0` класс молчит.

При положительном значении показывает, например:

```text
Selected 3/10: feature 17, mean R2 = 0.7024
```

Модуль `tqdm` не добавлен намеренно. Он рекомендован, но не обязателен. Чем меньше внешних зависимостей у файла для автопроверки, тем ниже риск, что среда курса не содержит нужный пакет.

### Сортировка результата

```python
self.selected_features_.sort()
```

Во время алгоритма порядок означает порядок выбора. После `fit` список приводится к возрастающему порядку индексов, как указано в описании атрибута.

## 6. Метод `transform`

```python
def transform(self, X: np.ndarray) -> np.ndarray:
    return X[:, self.selected_features_]
```

Этот метод ничего не переобучает.

Он просто применяет найденную маску колонок к любому совместимому датасету.

Пример:

```python
selector.selected_features_ == [1, 4, 8]
```

Тогда:

```python
X_train_selected = selector.transform(X_train)
X_test_selected = selector.transform(X_test)
```

Обе матрицы будут иметь три колонки в одинаковом порядке.

Это критично: train и test должны использовать один и тот же набор и порядок признаков.

## 7. Свойство `n_selected_features_`

```python
@property
def n_selected_features_(self) -> int:
    return len(self.selected_features_)
```

### Зачем `@property`

Без декоратора пришлось бы писать:

```python
selector.n_selected_features_()
```

С `@property` используем как обычный атрибут:

```python
selector.n_selected_features_
```

Но значение вычисляется динамически.

### Почему не хранить отдельное число

Если хранить и список, и число, они могут разойтись:

```python
selected_features_ = [1, 4, 8]
n_selected_features_ = 2  # ошибка состояния
```

Через `len` источник истины один — сам список.

## 10. Почему `fit` не возвращает `self`

В стандартном scikit-learn часто делают:

```python
return self
```

Но в выданном API явно указано:

```python
def fit(...) -> None:
```

И пример использования:

```python
selector.fit(X, y)
```

Поэтому решение следует шаблону и ничего не возвращает. Для автопроверки важнее соответствовать заданному контракту, чем самовольно улучшать API.

## 11. Что было бы ошибкой

### Ошибка 1. Оценивать каждый признак только отдельно

Неправильно:

```python
X[:, [candidate]]
```

на каждой итерации без уже выбранных признаков.

Тогда это не sequential selection, а однофакторное ранжирование.

Правильно:

```python
feature_subset = selected + [candidate]
```

### Ошибка 2. Выбрать минимальный score

Для `R²` больше — лучше. Нужен `max`, а не `min`.

### Ошибка 3. Считать score на train

Это выберет признаки, лучше всего переобучающие модель. Нужна cross-validation.

### Ошибка 4. Повторно выбрать тот же признак

После выбора его нужно удалить из `excluded_features`.

### Ошибка 5. Вернуть строки вместо колонок

Неправильно:

```python
X[self.selected_features_, :]
```

Это отберёт строки.

Правильно:

```python
X[:, self.selected_features_]
```

### Ошибка 6. Переименовать атрибут

Опечатка из текста `selected_feateures_` не должна попадать в код. Требуемое имя класса в шаблоне:

```python
selected_features_
```

### Ошибка 7. Добавить обязательную зависимость `tqdm`

Если её нет в grader environment, импорт разрушит весь файл ещё до тестов. Простой `print` реализует необязательный verbose без риска.

## 12. Как использовать класс на train/test данных корректнее

Для реального проекта нельзя выбирать признаки на train+test вместе.

Правильнее:

```python
selector.fit(X_train, y_train)

X_train_selected = selector.transform(X_train)
X_test_selected = selector.transform(X_test)

model.fit(X_train_selected, y_train)
predictions = model.predict(X_test_selected)
```

`X_test` никак не участвует в выборе признаков.

Для максимально честной оценки selector должен находиться внутри внешней схемы nested cross-validation.

## 13. Краткий алгоритм для запоминания

```text
1. selected = []
2. excluded = все индексы
3. current_score = -∞
4. Сделать не более max_features попыток:
   4.1. Для каждого кандидата:
        - взять selected + candidate
        - получить CV scores
        - посчитать mean
   4.2. Найти кандидата с максимальным mean
   4.3. Если selected уже не пуст и лучший mean <= current_score:
        - остановиться
   4.4. Иначе:
        - добавить победителя в selected
        - удалить его из excluded
        - current_score = лучший mean
5. Отсортировать selected
6. transform возвращает X[:, selected]
```
