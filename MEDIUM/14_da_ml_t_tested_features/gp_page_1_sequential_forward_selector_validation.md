# SequentialForwardSelector — page_1: валидация базового SFS и типичные ошибки

## 1. Что показал первый запуск grader

Первая отправка получила:

```text
20 / 100
```

Прошли:

```text
API test
Pylint test
```

Не прошёл основной тест алгоритма.

Сообщение grader:

```text
For random_state = 69 expected
[8, 9, 10, 17, 20, 26, 44, 46]

got
[8, 9, 10, 17, 20, 26, 31, 32, 44, 46]
```

Это очень полезная ошибка: она показывает, что класс, методы и стиль были корректными, но критерий остановки был неправильным.

---

## 2. Почему старая версия выбрала лишние признаки

После выбора восьми действительно полезных колонок текущий набор уже достиг лучшего среднего CV `R²`.

Но старая реализация продолжала цикл, потому что была написана логика:

```text
повторить ровно max_features раз
```

На девятой и десятой итерациях она всё равно находила «лучшего из оставшихся».

Проблема в слове «лучшего».

Лучший из плохих кандидатов всё ещё может быть плохим.

Например:

```text
текущий score              = 0.7100
candidate 31 score          = 0.7098
candidate 32 score          = 0.7097
остальные candidate scores  < 0.7097
```

`31` является лучшим среди оставшихся, но он хуже текущего набора.

Такой признак нельзя добавлять.

---

## 3. Правильный критерий

В начале:

```python
current_score = float("-inf")
```

После оценки всех кандидатов:

```python
best_feature = max(
    candidate_scores,
    key=lambda feature: candidate_scores[feature],
)
best_score = candidate_scores[best_feature]
```

До добавления выполняется:

```python
if self.selected_features_ and best_score <= current_score:
    break
```

После успешного добавления:

```python
current_score = best_score
```

---

## 4. Почему условие строгое

Используется:

```python
best_score <= current_score
```

А не только:

```python
best_score < current_score
```

При равенстве score новый признак не доказал никакой дополнительной ценности.

Он:

- увеличивает число входных колонок;
- делает пайплайн сложнее;
- может ухудшить интерпретируемость;
- увеличивает стоимость расчёта;
- не повышает выбранную метрику.

Поэтому равенство также означает остановку.

---

## 5. Почему первый признак выбирается всегда

Условие содержит:

```python
self.selected_features_
```

На первой итерации список пуст:

```python
[]
```

Пустой список интерпретируется как `False`, поэтому ранняя остановка не выполняется.

Алгоритм выбирает лучший одиночный признак.

После этого список становится непустым, и все дальнейшие кандидаты сравниваются с `current_score`.

## 7. Проверка алгоритмических инвариантов

### Уникальность

После выбора:

```python
excluded_features.remove(best_feature)
```

Поэтому один индекс нельзя выбрать дважды.

### Верхняя граница

```python
features_to_select = min(self.max_features, self.n_features_)
```

Количество выбранных признаков не превысит:

- `max_features`;
- фактическое число колонок.

### Реальное улучшение

После первого признака каждый следующий добавляется только при:

```text
best_score > current_score
```

### Согласованность transform

```python
selector.transform(X)
```

эквивалентен:

```python
X[:, selector.selected_features_]
```

### Повторный fit

В начале:

```python
self.selected_features_ = []
```

Поэтому старое состояние не переносится в новый запуск.

## 8. Граничные случаи

### `max_features` больше числа колонок

Допустим:

```text
X содержит 5 колонок
max_features = 10
```

Код использует:

```python
min(10, 5)
```

Максимум будет сделано пять попыток. Выхода за список не произойдёт.

### `max_features = 0`

Внешний цикл не запустится.

Результат:

```python
selected_features_ == []
n_selected_features_ == 0
transform(X).shape == (n_samples, 0)
```

### Улучшение прекращается раньше лимита

Это основной кейс задания.

При:

```text
max_features = 10
```

может быть выбрано:

```text
8 признаков
```

Если девятый уже не улучшает score.

### Равные candidate scores

`max` вернёт первый максимальный ключ в порядке обхода словаря.

Порядок кандидатов детерминирован:

```python
excluded_features = list(range(self.n_features_))
```

Затем итоговый список сортируется.

### Отрицательный `R²`

Это не ломает алгоритм.

Первый score сравнивается с `-∞`, поэтому лучший одиночный признак выбирается даже при отрицательном `R²`.

Далее добавляются только признаки, которые делают score строго выше.

## 9. Типичные ошибки

### Ошибка 1. Всегда выбирать ровно `max_features`

Это причина первой неудачной отправки.

### Ошибка 2. Оценивать каждый признак независимо

Неправильно:

```python
X[:, [candidate]]
```

на всех итерациях.

Правильно:

```python
X[:, selected_features + [candidate]]
```

SFS оценивает incremental value относительно уже выбранного набора.

### Ошибка 3. Выбрать максимальный индекс, а не максимальный score

Неправильно:

```python
best_feature = max(candidate_scores)
```

Это сравнит ключи словаря.

Правильно:

```python
best_feature = max(
    candidate_scores,
    key=lambda feature: candidate_scores[feature],
)
```

### Ошибка 4. Не удалить выбранный признак

Без:

```python
excluded_features.remove(best_feature)
```

одна колонка может быть выбрана несколько раз.

### Ошибка 5. Перезаписывать `selected_features_` внутри внутреннего цикла

Добавлять кандидата можно только после оценки всех оставшихся признаков.

### Ошибка 6. Использовать train score

Нужно использовать `cross_val_score`, иначе алгоритм будет сильнее переобучаться на шум.

### Ошибка 7. Создать собственную CV вместо переданной

Grader передаёт объект `cv`. Нужно использовать:

```python
cv=self.cv
```

### Ошибка 8. Вернуть имена вместо индексов

Условие ожидает список индексов колонок.

### Ошибка 9. Реализовать `n_selected_features_` как метод

Нужно:

```python
@property
def n_selected_features_(self):
    return len(self.selected_features_)
```

### Ошибка 10. Добавить t-тест в текущий файл

Тема курса шире задания. Текущий API проверяет базовую логику mean CV score и раннюю остановку. Дополнительная статистическая логика может изменить ожидаемый результат.

### Ошибка 11. Сделать `tqdm` обязательной зависимостью

`tqdm` рекомендован только для удобства. Простой `print` при `verbose > 0` безопаснее для grader environment.

### Ошибка 12. Проводить отбор на test

В реальном проекте:

```text
feature selection выполняется только на train
```

Test должен использоваться один раз для финальной честной оценки.

## 12. Финальная памятка

Правильный SFS в этом задании — это не:

```text
выбрать десять лучших признаков
```

Правильный SFS — это:

```text
последовательно добавлять лучший оставшийся признак,
пока он строго улучшает CV R²,
но выбрать не больше max_features.
```
