# GP Page 6 — исправление по эталонному решению

## Главный вывод

Предыдущая реализация не совпадала с эталоном в функции персональных рекомендаций.

## Как было в предыдущем варианте

Использовался стандартный вызов:

```python
model.recommend(...)
```

То есть модель напрямую ранжировала стримеров для пользователя.

С инженерной точки зрения это нормальный способ работы с ALS, но скрытые метрики курса рассчитаны под другую функцию.

## Что делает эталон

Эталон берёт:

```python
model.user_factors
```

Затем:

1. считает норму каждого user vector;
2. считает similarity заданного пользователя со всеми пользователями;
3. выбирает 100 наиболее похожих пользователей;
4. для каждого похожего пользователя берёт первый `streamer_name`;
5. возвращает эти имена в порядке similarity.

## Почему это важно

NDCG@K и MAP@K чувствительны к:

- составу рекомендаций;
- порядку рекомендаций;
- точному mapping;
- логике формирования top-K.

Даже более стандартная реализация через `model.recommend()` может получить низкий балл, если эталонные labels сформированы под user-user similarity.

## Другие отличия эталона

### Матрица строится прямо из строк

```python
sparse.csr_matrix(
    (
        data["total_time_stream"].astype(float),
        (data["user_id"], data["streamer_id"]),
    )
)
```

Отдельная агрегация не нужна: CSR суммирует повторяющиеся координаты.

### Гиперпараметры

```text
iterations = 12
factors = 100
regularization = 0.2
alpha = 100
random_state = 42
```

### Endpoint

Точное написание:

```text
/recomendations/user/{user_id}
```

В слове `recomendations` сохранена ошибка из условия.

### Пути

Оба файла берутся из переменных окружения:

```text
data_path
model_path
```
