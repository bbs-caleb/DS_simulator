## Что это за задача одним абзацем

У вас есть большой текст. Его нужно разрезать на кусочки («чанки») так,
чтобы каждый кусочек был **законченной мыслью**. Не «каждые 500 символов»,
а именно по смыслу. Для этого мы превращаем каждое предложение в вектор
чисел (эмбеддинг), смотрим, насколько сильно «прыгает» смысл между
соседними предложениями, и режем там, где прыжок аномально большой.

Это фундамент любого **RAG** (Retrieval-Augmented Generation) — то есть
любого чат-бота, который отвечает по вашей базе знаний.

## Ключевая подсказка про параметры (сэкономит вам час)

Число чанков зависит **только от `threshold`**, а не от буферов.

Почему: `threshold` — это перцентиль. Перцентиль 90 означает «взять
верхние 10 % расстояний». Если расстояний `D` штук, то точек разреза
будет примерно `D × (1 − threshold/100)`, а чанков — на один больше.

```
чанков ≈ D · (1 − threshold/100) + 1
=>
threshold ≈ 100 · (1 − (чанков − 1) / D)
```

Буферы (`buffer_back`, `buffer_forward`) влияют на то, **где именно**
пройдут разрезы, но почти не влияют на их количество.

Стратегия: сначала по формуле находим `threshold`, потом перебираем
буферы, пока границы не совпадут с картинкой.

## Частые причины потери баллов (проверьте перед сдачей)

| ❌ Ошибка | Как избежать |
|---|---|
| Браузер переименовал файл в `... (1).py` | Переименуйте обратно перед загрузкой |
| В файл с параметрами попали `import` или `print` | Там должны быть **только три строки присваивания** |
| В файле с классом остался лишний код (тесты, `visualize`, `print`) | Грузим ровно тот файл, что дан — ничего не дописываем |
| Изменили сигнатуру метода | Не трогайте `def ...` строки |
| `_calculate_distances` вернул `numpy.float64` вместо `float` | У нас стоит явный `float(...)` |
